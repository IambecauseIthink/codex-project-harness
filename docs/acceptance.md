## 可复现的负向场景

- 缺失任务、循环依赖、过期 expectedRevision 均拒绝。
- 两次同时派发只创建一个会话；模块范围冲突不能并行。
- 新任务版本不能被旧 Run 满足；业务规则变化后旧候选不能验收。
- 暂停后的迟到完成不复活任务；重启未知结果不自动重派。
- 回归失败产生缺陷；两次自动修复仍失败后阻塞。
- 构建成功、未运行测试、全跳过、超时、事故用例删除都不能冒绿。
- 改检查配置、候选源码、当前产品源码后，旧证据失效。
- 主线移动必须合并再重验；两个候选模块的结果都保留。
- 有效教训的检查移除被阻止；手工破坏配置也会被知识维护检查发现。
- 旧项目接入保留已有文档；未知能力不冒充已验证。
- 备份恢复不覆盖目标，不恢复访问令牌，不自动重放原执行。
- 临时清理保留被引用日志和长期知识。
- 缺少令牌、跨站 Origin 与不正确 Host 被拒绝。

## 开发过程中发现并修复的问题

1. **错误的代码指纹**：真实 Codex 候选首次集成被拒绝，原因是工作区检出后的普通读写权限与原文件不同。改为仅比较 Git 语义相关的执行位；保留原检查记录，候选重新检查和审查后集成成功。
2. **嵌套 Node 测试输出**：从 Node 测试进程启动被测项目时继承 `NODE_TEST_CONTEXT`，产生二进制 reporter 通道。运行器移除该内部变量；未知输出仍拒绝通过。
3. **半次状态推进可见**：并行压力检查曾看到 Run 已结束而 Task 仍在验证。关键推进改为写前日志事务，API 快照持锁读取。
4. **Git 状态前导空格**：通用 `.trim()` 会破坏 porcelain 状态行，导致把 Harness 配置修改错判为脏源码。仅去掉尾部空白，并加入针对性回归。
5. **窄屏导航可访问名称丢失**：隐藏文字后导航按钮难以被辅助工具定位。增加稳定 aria-label，实际浏览器复验。

这些问题的修复依据和回归入口也写入了本仓库自己的 Harness 知识记录。

## 尚未完成的人工桌面验收

原生线程创建、执行、持久 threadId、历史回读，以及看板链接与 threadId 一致均已实测。**“从链接在 Codex 桌面打开同一会话 → 用户续聊 → 回看 Harness”仍未标为通过。** 自动操作 Codex 原生桌面应用被计算机使用工具安全策略拒绝，因此没有绕过限制，也没有用浏览器测试替代这个结论。

可手动打开探针：`codex://threads/01a1726e-a961-7b03-9aa4-1219ced4eb44`。应能看到 `HARNESS_CONNECTION_OK`；在该会话继续回复后，用运行核对读取历史。工作台已记录这项待验收任务。

## 交付边界

- npm 包可本地安装，未发布到公共注册表；未安装系统级常驻服务。
- 当前只实现 schema v1 的严格读取与备份恢复；未知格式拒绝修改，没有虚构历史版本迁移器。
- 运行图保留有限事件和最近检查节点，完整原生聊天由 Codex 管理；影响图是显式关联，不是自动代码调用分析。
- 文档语义更新与教训提炼需要协调/知识维护角色执行。程序自动做结构检查、护栏检查、版本留存、归档和受限临时清理，不自动决定产品承诺的变化。
- 图布局库延迟加载，构建仍提示该独立 chunk 较大；主页包已与布局库分离。该提示不影响本次构建和浏览器验收。

完整技术计划中涉及的原生桌面接续和未来格式迁移，不能据本次已通过项目笼统宣称全部验收完成。
