# 长期维护与恢复

## 当前文档与历史

只把当前有效规则放进活跃记录。提案标 proposed，被替代的决策标 superseded 并指向有效后继，结束材料归档。旧任务和知识修改前保存 `history/.../rev-N.md`；Run 保留执行时的完整限定上下文与摘要，便于解释当时为什么这样做。

缺陷、教训与决策正文采用 Markdown。建议按以下内容写：

- 决策：问题、选择、理由、拒绝方案、后果、适用范围、替代关系。
- 缺陷：症状、复现、期望/实际、根因、修复任务、关闭条件、实际证据。
- 事故：影响、时间线、机制根因、修复、防复发资产、尚未解决项。
- 教训：适用条件、具体行动、失败样例、检查 ID、必需回归用例、退役依据。

每次版本收尾运行 `harness maintain --archive`。它检查引用、原文路径与教训护栏，并归档无未完成依赖的旧版本已结束任务。正文合并、规则语义更新、判断教训是否仍适用，应由知识维护角色根据真实改动完成，不按记录年龄删除。

有效约束、被拒绝理由、事故依据和验证资产永久可追溯。首版没有自动删除长期记录或工作区的操作；运行输出有大小上限，事件时间线保留最近 400 项。模型原始完整会话留在 Codex 的会话存储中。维护操作仅自动清除 `.harness/runtime/cache` 与 `runtime/logs` 中超过 30 天且没有记录引用的普通临时文件；跳过符号链接，保留长期证据。当前运行器不生成大型原始日志缓存。

## 异常恢复

| 情况                            | 如何处理                                                    |
| ------------------------------- | ----------------------------------------------------------- |
| 关闭看板                        | 后台服务继续；重新打开启动链接                              |
| 服务退出或休眠后连接断开        | `harness start`；未知运行先“核对原会话”                     |
| 原会话仍在执行                  | 不启动重复 turn；保留占位和工作区                           |
| 确认已停止                      | “继续原任务”复用原 threadId，或重新验证候选工作             |
| 创建请求响应丢失、没有 threadId | 停止自动派发，人工核对 Codex 会话，不能假定不存在而重新创建 |
| 自动修复两次仍失败              | 查看保留的缺陷、输出和工作区，重新定位后手动继续            |
| 运行中目标改变                  | 旧版本结果不可验收；先暂停旧 Run，再授权新版本              |
| 主目录有未提交改动              | 先保存或由用户整理基线；系统不替你丢弃改动                  |
| 并行任务基线落后                | “更新基线并重验”；在工作区合并当前主线后再次检查和审查      |
| 集成后检查失败                  | 保留集成提交，验收不完成；继续修复，不能把失败结果标成完成  |

没有 threadId 的未知创建是首版刻意保留的人工核对边界；可以从运行记录中的工作区、时间和任务标题在 Codex 核对。不要手工捏造线程编号。保存实际 ID 前的进程崩溃无法仅靠本地记录自动证明原会话未创建。

## 备份与还原

```sh
harness backup /项目之外/全新备份目录 --project /项目
harness restore /备份目录 /空的恢复项目目录
```

备份前暂停活动运行。备份覆盖项目源码、Git、长期记录、事务状态与未结束工作区；排除依赖缓存、服务锁、访问令牌和脆弱的工作区 `.git` 指针。恢复必须使用空目录，保留原项目。系统在恢复的 Git 仓库里重建工作区并还原未提交文件，运行状态设为 unknown，关闭自动派发。核对后恢复原线程时传入恢复工作区 cwd。

备份不包含 Codex 账号登录信息，也不复制全局 Codex 会话数据库；原生会话历史仍由 Codex 管理。换机器时须另外保留官方 Codex 会话/身份环境，否则只能依据 Harness 上下文与源码人工接续。

系统不会自动替你提交每次项目记录；将 `.harness` 长期目录和业务代码一起纳入 Git/备份，runtime 与 worktrees 保持忽略。备份是本地副本，还需要自己的设备备份策略。

## 升级与兼容

当前格式版本为 `schemaVersion: 1`。版本由 schema 严格校验；未知未来版本拒绝载入，不能静默降级或覆盖。升级前停止服务、备份、安装新包、运行检查，再启动恢复核对。本首版没有历史 schema 可迁移，不虚构 v0 数据转换器；未来格式变化必须新增显式转换、备份和往返验收。

Codex 适配器使用本机协议握手，并在每次真实操作中处理不支持方法和模型版本错误。已知兼容性错误会停住自动派发，排队任务与工作区保留；更换可执行版本并重启后再核对与继续。`harness doctor` 只能证明协议连接，不能替代真实任务验收。

## 首版边界

单人本机服务，无多用户权限系统、云端调度或团队远程同步。图是显式追溯关系，不是自动静态代码分析。图显示有上限，但历史记录可检索。完整用户流程是否被覆盖，仍取决于项目配置的测试与产品体验；模型审查本身不能保证软件正确。
