# 快速上手

Harness 是一套给其他软件项目使用的开发工具。每个产品都有自己的目录、代码和 `.harness` 记录；工具仓库负责提供程序和可复制的开发指引。

## 方式一：只使用开发指引

把仓库根目录的 [AGENTS.md](../AGENTS.md) 复制到你要开发的产品项目根目录，在 Codex 中打开该产品目录，然后描述产品目标即可。已有 `AGENTS.md` 时，让 Codex 保留原有约束并合并通用规则。

这会提供需求变更、分工、验证和记忆维护约定。要使用看板、依赖图和自动派发，请继续下面的完整接入。

## 方式二：使用完整工作台

### 1. 安装工具

首版使用 macOS，需要 Node.js 20.9 或更新版本、Git，以及已登录的 Codex 桌面应用。打开终端，在你存放工具的目录执行：

```sh
git clone https://github.com/IambecauseIthink/codex-project-harness.git
cd codex-project-harness
npm ci
npm run build
HARNESS_DIR="$PWD"
```

后续接入多个产品时，复用这份工具即可。下面的命令在同一个终端窗口执行；新开终端时，将 `HARNESS_DIR` 设置为这个工具目录的绝对路径。

### 2. 接入一个产品项目

将下面第一行改成你的产品目录绝对路径。已有项目填写现有目录；新产品可填写一个新的目录。

```sh
PRODUCT_DIR="/你的产品项目绝对路径"
mkdir -p "$PRODUCT_DIR"
cp -n "$HARNESS_DIR/AGENTS.md" "$PRODUCT_DIR/AGENTS.md"
node "$HARNESS_DIR/dist/cli.js" init "$PRODUCT_DIR" "我的产品"
node "$HARNESS_DIR/dist/cli.js" connect --project "$PRODUCT_DIR"
node "$HARNESS_DIR/dist/cli.js" start --project "$PRODUCT_DIR" --port 4318
```

`cp -n` 保留目标目录中已有的同名文件；如果已有指引，随后让 Codex 合并规则。`init` 创建项目记录、角色配置和技能；`connect` 写入本机 MCP 入口；`start` 启动后台服务并输出带访问令牌的本地链接。打开该完整链接进入看板。端口被占用时改用另一个本地端口。

然后在 Codex 中打开或重新加载 **产品项目目录**，使项目的 MCP 与技能配置生效。看板左侧也可以接入更多产品，由同一个服务管理。

### 3. 让 Codex 完成第一次项目准备

可以直接发送以下文字，并补充你的业务背景：

> 请按这个产品项目的 AGENTS.md 和 harness-work 技能工作，通过 Harness 获取概览。我的产品面向【谁】，解决【什么问题】，第一版要完成【哪些用户流程】。请先盘点已有代码、有效文档与功能；未经验证的能力标为未知。明确当前目标、验收场景和受影响的旧行为，建立任务与依赖，配置能实际运行的检查，并准备 Git 基线。保留已有文件和用户改动。涉及产品取舍的问题集中告诉我，常规技术实现由你处理。确认版本范围后再派发实现任务。

新项目先建立最小产品骨架、真实检查和 Git 提交；旧项目保留原仓库并整理未提交改动。保存检查配置及代码基线后再派发，工作区才能包含正确的代码和检查。检查的配置示例见 [接入与适配](adapters.md)。

### 4. 日常开发

1. 在 Codex 中提需求，说明希望改变什么、哪些旧行为必须保留；Agent 更新任务、依赖和验收条件。
2. 在看板确认范围并授权任务。首次使用建议手动派发，熟悉后再启用自动派发；只有已授权、依赖就绪的任务会执行。
3. 通过任务卡、依赖图和运行追踪查看进度、阻塞、检查结果与关联会话。需要用户决定的业务问题由用户回答。
4. Agent 完成实现、检查和独立审查后，提供候选版本的体验方式。实际体验核心流程，再使用看板的“已体验，验收并集成”；集成后系统重新检查。
5. 每个版本收尾让 Agent 更新当前文档，沉淀缺陷和教训，整理归档，并记录下一步。

后续新会话可以说：

> 请从当前项目的 AGENTS.md 和 Harness 记录恢复工作，说明当前版本目标、已确认规则、已知缺陷与下一项可执行任务。只读取本次任务相关上下文，并继续已授权工作。

### 5. 停止、恢复与保存

关闭看板不会停止后台服务。需要停止时运行：

```sh
node "$HARNESS_DIR/dist/cli.js" stop --project "$PRODUCT_DIR"
```

下次用同样的 `start` 命令恢复，程序会核对已有运行。把产品代码和 `.harness` 长期记录提交到产品自己的 Git 仓库；运行缓存、访问令牌及临时工作区保持忽略。备份和恢复见 [维护说明](maintenance.md)。
